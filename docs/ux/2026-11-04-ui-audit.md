# Agent City UI audit

Date: 2026-11-04. Source: the live city on port 4321 (HQ Work and Configure, the Decisions panel, the Buildings box) and the 19 files in `packages/client/src/ui`.

## Summary

The UI has 11 nouns on screen and no single place per noun. A project shows in 4 places, a merge button in 2, things that wait on the player in 3. The goal board, which is the main work surface, sits 4 steps deep: walk into HQ, open Work, unfold Buildings, pick Software house. Every box has the same border, font and weight, so nothing reads as more important than anything else.

The fix is an object model of 4 nouns (Project, Goal, Task, Agent), one Inbox for everything that waits on the player, and 3 surface levels by importance. Buildings stay on the map as places and shortcuts. They stop holding data panels.

## Findings

### Structure

1. Project appears in 4 places with 4 different shapes. HQ Work shows branches and runs. Configure shows edits and budget. The Goal board shows goals. The Software house shows agents. The player has to visit all 4 to know one project's state.
2. The goal board is 4 steps deep and hidden behind a building dropdown. It is the surface the player uses most.
3. The Buildings box puts building views inside HQ, so HQ contains the city that contains HQ. The dropdown lists Plot 1 to Plot 6 with nothing in them.
4. Three surfaces hold things that wait on the player: the Approvals box (tool calls), the Decisions panel (task questions, plan OKs), and the merge lists. The HUD counter "decisions: 5" counts only one of them.
5. Merge has 2 buttons with 2 labels: "Merge" in HQ Work > Projects and "Merge into main" in Waiting to merge. Same action, same branches.
6. Runs show in 3 places: HQ Work > Projects, the Progress panel, Software house > Working on.
7. Terminal has 2 buttons: the dock "Terminal (T)" and the HQ bar "Terminal (T)".
8. Performance and City both show runs and spend for 7 days. Activity is a third stats box, folded and empty.

### Hierarchy and reading

9. Every box has the same blue border, white fill and about 9px monospace text. An empty "no pending approvals" box weighs the same as a blocked goal.
10. The Decisions panel floats in the map center over HQ's interior. It acts like a dialog but does not block anything, and it covers the avatar.
11. The goal board squeezes 5 kanban columns (todo, doing, review, approval, done) into a 150px side column. 3 columns are visible; the rest scroll sideways.
12. Global controls sit in 3 bars: top left (Roofs, online, Resume all, decisions, bell), top center (HQ modes, Terminal, close, error text), bottom (Chat, Terminal, last chat line).
13. Raw internals reach the player: "agent/boss-20261101-222607", "claude-sub/haiku", "tier 2", full Windows paths, the last commit subject of a branch ("Merge remote-tracking branch 'origin/main' into codex/...").
14. Chart day labels read "Q S S D S T Q" (Portuguese initials from the browser locale). Two S and two Q are ambiguous.
15. Spend reads $0.00 everywhere because the agents run on the Claude subscription. Tokens or run minutes would carry information.

### Wording and states

16. 9 status words with no shared color code: idle, thinking, active, paused, blocked, done, waiting for your OK, run stopped: budget, 3 to merge. "Decision", "approval" and "waiting for your OK" name the same idea.
17. Verbs differ per box: "Create agent", "Create project", "Add skill", "Add API", "Add server".
18. Agents list a building ("worker · software") as if the building were a team.

### Defects seen

19. Goal "Have the game ready for general availability" reads "active · 0 of 0 done" while it lists 5 tasks.
20. The Decisions panel offers Roll back on tasks with no checkpoint. Clicking it prints "no checkpoint yet" in the panel and again in the HQ bar, where it stays.
21. Three branches (boss-20261101-222607, boss-20261102-143949, zed-20261102-132611) show the same 11 commits and the same diff. Nothing marks them as duplicates.
22. A project cannot be removed. Agents, APIs, MCP servers and skills each have Remove in Configure; projects only have Pause. The CLI has no `project remove` either.

## Proposed model

Four nouns, nested: Project > Goal > Task, with Agents assigned to tasks. A Run, a branch and a merge are details of a Task. A Building is a place on the map.

| Noun | Lives in | Edited in |
|---|---|---|
| Project | Project view | Settings > Projects |
| Goal | Project view, left list | Project view |
| Task | Project view, kanban; Task drawer for detail | Task drawer |
| Agent | Map sprite; Agent card | Settings > Agents |
| Inbox item | Inbox | Inbox (answer in place) |

## Proposed surfaces, by importance

1. Top bar (always on, one row). City status, Inbox count, Stop all, Chat, Terminal, Roofs. One button per action. The bell becomes a setting.
2. Inbox (right drawer, opens on the count). Every item that waits on the player in one card format: project, agent, one sentence, 2 or 3 buttons. Kinds: question, tool approval, plan OK, merge. Sorted oldest first. Roll back shows only when a checkpoint exists.
3. Project view (the main panel, full width when open). Project tabs across the top. Goals as a list on the left with "3 of 5 done". The selected goal's tasks as a kanban across the full width. A task opens a drawer with its log, diff, preview, Retry, Cancel, Roll back and Merge. Merge lives here and in the Inbox, nowhere else.
4. Overview (HQ, opens on H). One row per project: running, blocked, waiting on you, today's tokens. A row opens the Project view. One Stats tab holds the 7 day numbers and activity.
5. Settings (Configure). Agents, Projects (folder, edits, budget), Models and APIs, MCP servers, Skills. Every list uses "Add".

The map keeps its role as the live picture. Agents sit at desks, buildings show a progress ring, and walking into the Software house opens the Project view. The building sign keeps its name and purpose line. The Buildings box and the building dropdown go away.

## Visual rules

- 3 surface levels: bar (thin, no border), drawer (raised, shadow), panel (full height). Boxes inside a panel lose their borders and use headings.
- Body text 12px minimum, headings 14px. Monospace only for paths, branches and logs.
- 5 status colors, one word each: blue running, amber needs you, red blocked, green done, gray idle. Paused is gray with the word "paused".
- Empty sections collapse to one line or hide.
- Names before ids: goal titles in place of branch names, project names in place of paths, model names in place of "claude-sub/haiku".

## Order of work

1. Fix defects 19, 20 and 21, and add project Remove (22). Remove asks first, stops the project's runs, drops its goals, tasks and branches from the city, and leaves the linked folder on disk untouched.
2. Inbox: merge Approvals, Decisions and merge lists into one drawer and one counter.
3. Project view: move the goal board out of Buildings into a full panel with the task drawer. Remove the Buildings box.
4. Overview: one row per project, linking to the Project view; fold Performance, City and Activity into Stats.
5. Top bar and visual rules: one bar, type scale, status colors, wording pass.
